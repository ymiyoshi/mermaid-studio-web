# Mermaid Studio Web

ブラウザだけで動く Mermaid エディタ。設計は [docs/design.md](docs/design.md) を参照。

**公開版: <https://ymiyoshi.github.io/mermaid-studio-web/>**（インストールせずにブラウザで使える。PWA としてインストールすると、オフラインでも動き、`.mmd` / `.mermaid` を開ける）

## 使い方

```sh
npm install      # .npmrc で legacy-peer-deps を有効にしている（npm 10 の依存解決の不具合回避）
npm run dev      # 開発サーバー
npm test         # 単体・結合・コンポーネントのテスト（Vitest）
npm run coverage # 上と同じテストを、カバレッジつきで
npm run test:e2e # E2E テスト（Playwright。本番ビルドを作って、インストール済みの Chrome で動かす）
npm run perf     # 設計書 §11 の応答時間を本番ビルドで測り、表で出す（目標を超えても失敗にはしない）
npm run build    # 型チェック + 本番ビルド（dist/、CSP 付き）
npm run preview  # 本番ビルドの確認
```

## 公開（GitHub Pages）

`main` に push すると、`.github/workflows/deploy.yml` がテストを通したうえで `https://<ユーザー名>.github.io/<リポジトリ名>/`（このリポジトリでは <https://ymiyoshi.github.io/mermaid-studio-web/>）に公開する。初回だけ、リポジトリの Settings → Pages で Source を「GitHub Actions」にする。

サブパスに置くので、ビルド時に `--base "/<リポジトリ名>/"` を渡している。アプリの中で `public/` のファイルを参照するときは、`/favicon.svg` のような絶対パスではなく `import.meta.env.BASE_URL` を前に付ける。

## 依存の更新（Renovate）

`renovate.json` の設定で、Renovate が毎日（日本時間の 0〜9 時）更新を確かめて PR を作る。

- メジャー以外の npm の更新は 1 本の PR にまとめ、CI（`.github/workflows/ci.yml` の型チェック・テスト・ビルド・E2E・依存の脆弱性の確認）が通ったら自動でマージする。マージされると、そのまま GitHub Pages に公開される
- メジャー更新・mermaid・GitHub Actions は自動でマージしない（mermaid は SVG の見本を作り直す必要がある。AGENTS.md「mermaid の版」）
- 公開されてから 3 日たっていない版は使わない（`minimumReleaseAge`。乗っ取られた版はたいてい数日のうちに見つかって取り下げられる）

サプライチェーン攻撃への備え:

- `.npmrc` の `ignore-scripts=true` で、依存パッケージのインストール時のスクリプトを動かさない
- CI で `npm audit signatures` を走らせ、レジストリの署名と来歴を確かめる
- GitHub Actions はタグではなくコミットの SHA で固定する（Renovate が SHA ごと更新する）
- ワークフローの権限は既定で読み取りだけ。checkout は資格情報を残さない

自動マージを CI で止めるには、GitHub 側で「Allow auto-merge」を有効にし、`main` のルールセットで CI の `check` と `dependency-review` を必須にしておく（Renovate の GitHub App も入れておく）。

## テスト

| 種類 | 場所 | 内容 |
|---|---|---|
| 単体 | `tests/*.test.ts` | 履歴ツリー、入力のまとめ方、各図種の操作（追加・削除・プロパティ）、表、Markdown、URL 共有、保存形式 |
| SVG の対応付け | `tests/svgMapping.test.ts` | mermaid が実際に描いた SVG（`tests/fixtures/rendered-svg.json`）を図種ごとにソースへ対応付ける回帰テスト |
| 性質ベース | `tests/property.test.ts` | ランダムな図に操作を当て、結果が `mermaid.parse` を通る・コメント行と対象外の行が変わらないことを確かめる（fast-check） |
| 結合 | `tests/session.test.ts`、`tests/files*.test.ts`、`tests/launchFiles.test.ts` | 文書の管理・保存と読み込み直し・複数タブの書き込み権、ファイルの読み書き・外部での変更・バックアップ・共有リンク、OS から渡されたファイルを開く（ファイルの関連付け） |
| コンポーネント | `tests/components.test.tsx` | 入力欄（IME・確定時の反映）、色の欄（パレット）、タグ、表、履歴、一覧、ラベルの直接編集（React Testing Library） |
| E2E | `e2e/*.spec.ts` | 起動、テキストと図の編集、undo と再読み込み、表、共有リンク、PNG 出力、複数タブ、オフライン、狭い画面、ファイルの関連付け（launchQueue）、カラーパレット、タイムラプスの書き出し |

mermaid の版を上げたときは、`tests/fixtures/capture.js` で SVG の見本を作り直し、`npm test` と `npm run test:e2e` が通ることを確かめる。
E2E の `test.fail` は既知の不具合を表す（直したら外す）。

### 既知の制限・未実装

- `zenuml` は mermaid 本体に含まれない外部図種のため対象外
- 英語の UI では、テンプレートの中身（図の文言）は日本語のまま（テンプレートの名前と、図からの操作で差し込む文言は英語になる）
- シーケンス図で、活性化（+ / -）や create / destroy の付いたメッセージを上下に動かすと構文が壊れることがある（検証で弾いて反映しない）
- 設計書 §11 の応答時間のうち、200 ノードのフローチャートでのテキスト入力から再描画までが目標（300ms）を超える（2026-10-24、開発用の Windows PC で中央値 691ms。描画前の 150ms の待ちを含む）。起動と図の操作は目標内
- state 図の遷移は、SVG に端点の情報が無いため、描画の順番だけで対応付けている
- IME（日本語入力）の扱いは実装済みだが、実機での確認はまだ
- ファイルの上書き保存は Chromium 系のみ。Firefox / Safari では保存がダウンロードになる
- ファイルの関連付けは、インストールした Chromium 系（パソコン）のみ。ダブルクリックで直接開くには、OS の「既定のアプリ」で選ぶ
- タイムラプスの書き出しは WebM のみ（GIF は未対応）。動画の書き出しを同時にいくつも走らせると空になる（そのときは通知を出す）
- PNG 出力では、foreignObject を使う図種（journey など）のラベルを単純な SVG テキストに置き換える
- バックアップにはファイルとの結び付き（ハンドル）は含まれない

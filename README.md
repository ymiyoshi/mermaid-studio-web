# Mermaid Studio Web

ブラウザだけで動く Mermaid エディタ。設計は [docs/design.md](docs/design.md) を参照。

## 使い方

```sh
npm install      # .npmrc で legacy-peer-deps を有効にしている（npm 10 の依存解決の不具合回避）
npm run dev      # 開発サーバー
npm test         # 単体・結合・コンポーネントのテスト（Vitest）
npm run coverage # 上と同じテストを、カバレッジつきで
npm run test:e2e # E2E テスト（Playwright。本番ビルドを作って、インストール済みの Chrome で動かす）
npm run perf     # 設計書 §11 の応答時間を本番ビルドで測り、表で出す（目標を超えても失敗にはしない）
npm run build    # 型チェック + 本番ビルド（dist/、CSP 付き）
npm run preview  # 本番ビルドの確認
```

## 公開（GitHub Pages）

`main` に push すると、`.github/workflows/deploy.yml` がテストを通したうえで `https://<ユーザー名>.github.io/<リポジトリ名>/` に公開する。初回だけ、リポジトリの Settings → Pages で Source を「GitHub Actions」にする。

サブパスに置くので、ビルド時に `--base "/<リポジトリ名>/"` を渡している。アプリの中で `public/` のファイルを参照するときは、`/favicon.svg` のような絶対パスではなく `import.meta.env.BASE_URL` を前に付ける。

## テスト

| 種類 | 場所 | 内容 |
|---|---|---|
| 単体 | `tests/*.test.ts` | 履歴ツリー、入力のまとめ方、各図種の操作（追加・削除・プロパティ）、表、Markdown、URL 共有、保存形式 |
| SVG の対応付け | `tests/svgMapping.test.ts` | mermaid が実際に描いた SVG（`tests/fixtures/rendered-svg.json`）を図種ごとにソースへ対応付ける回帰テスト |
| 性質ベース | `tests/property.test.ts` | ランダムな図に操作を当て、結果が `mermaid.parse` を通る・コメント行と対象外の行が変わらないことを確かめる（fast-check） |
| 結合 | `tests/session.test.ts`、`tests/files*.test.ts` | 文書の管理・保存と読み込み直し・複数タブの書き込み権、ファイルの読み書き・外部での変更・バックアップ・共有リンク |
| コンポーネント | `tests/components.test.tsx` | 入力欄（IME・確定時の反映）、タグ、表、履歴、一覧、ラベルの直接編集（React Testing Library） |
| E2E | `e2e/*.spec.ts` | 起動、テキストと図の編集、undo と再読み込み、表、共有リンク、PNG 出力、複数タブ、オフライン、狭い画面 |

mermaid の版を上げたときは、`tests/fixtures/capture.js` で SVG の見本を作り直し、`npm test` と `npm run test:e2e` が通ることを確かめる。
E2E の `test.fail` は既知の不具合を表す（直したら外す）。

## 構成

| パス | 内容 |
|---|---|
| `src/core/history.ts` | ツリー型の履歴（ChangeSet の forward/inverse、スナップショット、ジャンプ、チェックポイント、分岐の整理） |
| `src/core/coalesce.ts` | 入力を履歴 1 ステップにまとめる規則 |
| `src/core/session.ts` | 文書の状態。すべての変更が通る `applyChanges()`、保存、複数タブ制御 |
| `src/storage/` | IndexedDB（文書・履歴・ファイルの結び付き・サムネイル・設定）、Web Locks / BroadcastChannel |
| `src/io/` | ファイルの読み書き（.mmd / .md）、画像の書き出し（SVG / PNG）、バックアップ（JSON）、URL 共有 |
| `src/render/` | mermaid による検証と描画、エディタ用ハイライト、サムネイル |
| `src/plugins/` | 図種プラグイン（下の表）と、汎用フォールバック（ラベル編集） |
| `src/ui/` | 画面（一覧・エディタ・図・プロパティパネル・履歴） |

## 図種ごとの編集

| 図種 | 図からの編集 |
|---|---|
| flowchart | ノード（追加・次のノード（Tab）・接続・サブグラフにまとめる・削除・ID・ラベル・形 14 種類＋ @{ shape } の 39 種類・所属するサブグラフ・クラス・塗り / 枠線 / 文字の色）、エッジ（元と先の付け替え・向きの反転・間にノードを挟む・削除・ラベル・線の種類（見えない線を含む）・長さ・線の色と太さ）、サブグラフ（追加・中にノード（Tab）・接続・枠を外す・中身ごと削除・ID・題名・中の向き・色）、クラスの定義（表）、図の向き・題名。ラベルの無いノード・エッジ・サブグラフ・参加者も、ダブルクリックでラベルを付けられる |
| sequence | ドラッグでの並べ替え（参加者は左右、メッセージ・注釈・枠は上下。枠の中へも外へも）、参加者（追加・削除・並べ替え・ID・表示名・種類 8 つ）、メッセージ（追加・返事の追加・削除・上下の移動・送り手と受け手・矢印・本文・活性化）、注釈（追加・削除・本文・位置・参加者）、枠 loop / alt / opt / par / critical / break（囲む・外す・中身ごと削除・種類・条件・else などの区切りの追加と削除）、題名、通し番号 |
| class | クラス・メンバー・関係の追加・削除、関係の種類・多重度・ラベル、クラス名・表示名・注釈 |
| state | 状態・次の状態・遷移の追加・削除、表示名・名前、遷移のラベル |
| ER | エンティティ・属性・リレーションの追加・削除、多重度・線・ラベル、エンティティ名 |
| mindmap / kanban | 子・兄弟（列・カード）の追加、部分木ごとの削除・並べ替え、テキスト・形 |
| pie / gantt / timeline / journey / gitGraph / quadrant / xychart / sankey / packet / radar / treemap / C4 / requirement / architecture / usecase | 表で行の追加・削除・並べ替え・値の変更、図全体の設定（タイトルなど） |
| block | ブロック（追加・次のブロック（Tab）・入れ子の中に追加・削除・ラベル・形 12 種類・幅）、入れ子のブロック（幅・中の列の数・中身ごと削除）、矢印（追加・削除）、図全体の列の数 |
| 上記以外 | ラベルの直接編集のみ（汎用フォールバック） |

すべての操作は、`mermaid.parse` で検証してから反映し、変更する行以外（コメント・空行・インデント）には触れない。

### 既知の制限・未実装

- `zenuml` は mermaid 本体に含まれない外部図種のため対象外
- 英語の UI では、テンプレートの中身（図の文言）は日本語のまま（テンプレートの名前と、図からの操作で差し込む文言は英語になる）
- シーケンス図で、活性化（+ / -）や create / destroy の付いたメッセージを上下に動かすと構文が壊れることがある（検証で弾いて反映しない）
- 設計書 §11 の応答時間のうち、200 ノードのフローチャートでのテキスト入力から再描画までが目標（300ms）を超える（2026-10-24、開発用の Windows PC で中央値 691ms。描画前の 150ms の待ちを含む）。起動と図の操作は目標内
- state 図の遷移は、SVG に端点の情報が無いため、描画の順番だけで対応付けている
- IME（日本語入力）の扱いは実装済みだが、実機での確認はまだ
- ファイルの上書き保存は Chromium 系のみ。Firefox / Safari では保存がダウンロードになる
- タイムラプスの書き出しは WebM のみ（GIF は未対応）。動画の書き出しを同時にいくつも走らせると空になる（そのときは通知を出す）
- PNG 出力では、foreignObject を使う図種（journey など）のラベルを単純な SVG テキストに置き換える
- バックアップにはファイルとの結び付き（ハンドル）は含まれない
